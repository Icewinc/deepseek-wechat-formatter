# AI 使用说明

## 1. 使用的工具与角色

| 工具 | 用途 |
| --- | --- |
| Codex（本会话） | 产品规划、技术选型、编码实现、自测、文档整理 |
| 联网检索（官方来源） | 核对 DeepSeek 公开信息与用户协议中的商标边界 |
| 网页抓取 | 读取 DeepSeek 官网、透明度中心、用户协议、发布索引 |
| imagegen | 生成原创社交分享图（og.png），不复制官方 LOGO |
| 无头 Chrome + DevTools 协议 | 真实浏览器交互自测、结构/样式断言、演示截图 |
| Node / npm / Vinext | 项目脚手架、依赖、构建与测试 |

## 2. 各环节如何使用 AI

### 2.1 需求拆解与方案

- AI 把原始题目拆成“可运行产物 + 项目说明 + 真实演示”三组交付；
- 在动手前先做只读盘点（工作区为空、非 Git 仓库、环境版本），再列出“具体文件—具体改动—原因”清单，经用户授权后开工。

### 2.2 品牌资料核对

- 读取 DeepSeek 官网/透明度中心确认品牌定位与最新模型信息（V4 系列）；
- 读取用户协议第 6.2 条，确认未经许可不得使用“DeepSeek”商标、LOGO 等品牌特征；
- 结论：产品以“演示项目”名义使用文字名称，**不复制官方 LOGO、不仿制官网布局**，页面明确标注与官方无隶属关系；
- 示例文章根据官方公开信息重新组织，不整段复制官方原文。

### 2.3 开发与自测

- AI 编写了排版规则引擎（`lib/formatter.mjs`）与交互界面；
- 用单元测试覆盖结构识别、转义、渲染；用无头 Chrome 做端到端自测（点击排版、检查 375px 预览、验证复制载荷）；
- 所有断言结果记录在 `demo/qa-result.json` 与 `docs/test-report.md`。

## 3. AI 出现的问题与校正过程

| 问题 | 现象 | 校正方式 |
| --- | --- | --- |
| 官方页面读取超时 | DeepSeek 8 月 13 日发布页抓取超时 | 改用可直接读取的官方发布索引与用户协议交叉核对；示例文章标注为“基于公开信息重组”，不宣称引用了未读到的原文 |
| 沙箱无法写 `.git` | 初始化器报 `.git: Operation not permitted` | 在用户已授权范围内单独补建本地 Git 仓库 |
| npm 缓存目录被污染 | `npm ci` 报 cache 含 root 文件、EPERM | 清理不完整 node_modules，改用隔离临时缓存完成安装 |
| apply_patch 语法限制 | 同一文件“删除+新增”被拒 | 拆分为“先删除、后新增”两步完成 |
| 开发期 500 | 删除旧 globals.css 瞬间 HMR 报“文件不存在” | 重建文件后恢复，最终构建与页面均 200 |
| 首轮 E2E 点击无效 | 页面未完成 React 水合时点击不生效 | 增加“等待 readyState + 水合等待 + 点击后轮询”机制 |
| favicon 404 | 无头 Chrome 请求 /favicon.ico | 补充 favicon.svg/.ico 并验证控制台零错误 |
| 图片不可人工目检 | 本会话模型不支持图片输入 | 用 DOM 结构 + 计算样式断言验证截图对应状态；最终截图请提交者目检 |
| 在线部署连接器不可用 | 当前会话没有 Sites 发布连接器 | 如实说明：交付本地可运行版本与运行说明，在线私有预览作为后续可选项 |

**未自动验证的边界（本次不追）**

- Safari 等非 Chromium 浏览器的富文本复制：本次不验证、不列入验收；
- 演示截图的人工目检：AI 无法看图，建议提交者快速扫一眼（可选）。
