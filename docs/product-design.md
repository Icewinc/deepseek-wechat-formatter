# 产品设计说明 · DeepSeek Content Studio

> 品牌专属公众号排版器（笔试演示原型），品牌示例：DeepSeek

## 1. 背景与目标

品牌方官方类公众号（例如“DeepSeek”）的运营同学经常需要把已写好的文字稿排成固定风格的公众号文章。常见问题是：

- 每次都要手动调整字号、行距、配色、重点样式，重复劳动；
- 不同小编排出的风格不一致，品牌感被稀释；
- 直接粘贴到公众号编辑器后样式丢失，需要二次修复。

本产品定位：**粘贴成稿 → 一键排版 → 复制到公众号**。不做内容创作，只做“风格固定、复制可用”的排版环节。

## 2. 目标用户与场景

- 品牌公众号小编：把审稿通过的文字稿快速排成品牌版式；
- 品牌市场/内容团队：保证同一品牌在不同文章上保持一致的视觉语言；
- 演示场景：不登录、不付费、不接模型 API，打开页面即可体验完整流程。

## 3. 核心流程

1. 用户把写好的文章文字粘贴到左侧编辑区；
2. 系统实时识别文章结构（标题、副标题、导语、章节、正文、列表、引用、重点卡片）；
3. 点击“一键排版”，右侧按公众号 375px 宽度生成固定品牌版式预览；
4. 点击“复制到公众号”，复制包含内联样式的富文本和纯文本两个格式；
5. 用户到公众号编辑器直接粘贴，样式保留。

## 4. 关键功能设计

### 4.1 轻量结构语法

产品不要求用户学习复杂标记，支持常见写作习惯：

| 输入写法 | 识别结果 | 说明 |
| --- | --- | --- |
| 第一行 | 主标题 | 自动去掉 `#` 前缀 |
| 第一行后的短行 | 副标题 | 长度 ≤ 36 且不是标题/列表/引用 |
| `导语：……` | 导语卡片 | 支持 导语/摘要/引言 |
| `## 章节`、`一、章节`、`1. 章节` | 章节标题 | 自动编号 SECTION 01/02 |
| 普通段落 | 正文 | 15px、1.95 行高、两端对齐 |
| `- 项目` / `1. 项目` | 列表卡片 | 数字徽标 + 项目行 |
| `> 引用` | 引用块 | 居中文案样式 |
| `重点：……` | 重点卡片 | 品牌蓝左边线 + KEY POINT 标签 |
| `**加粗**` / `[[高亮]]` | 行内强调 | 品牌深蓝加粗/高亮底 |
| `---` | 分隔线 | 品牌蓝短横线 |

### 4.2 固定品牌规则（锁版式）

所有视觉参数集中在排版器内部，用户不可随意改色，保证品牌一致性：

- 主标题：27px、深蓝 #172B55、加粗；
- 正文：15px、行高 1.95、深灰蓝 #3B4A60、两端对齐；
- 品牌强调色：#3367F6；深色文字：#173B8F；
- 导语卡片：浅蓝底 #F7F9FD 圆角；
- 重点卡片：左侧 4px 品牌蓝边线 + KEY POINT 标签；
- 章节标题：SECTION 编号 + 底部细线；
- 文章头尾：DEEPSEEK · PRODUCT UPDATE / INTO THE UNKNOWN 结束区。

### 4.3 公众号兼容的复制方案

公众号编辑器对站外 CSS 支持有限，因此：

- 所有样式均写入元素 `style` 属性（内联样式），不依赖本站样式表；
- 复制时同时写入 `text/html` 与 `text/plain`，兼顾富文本粘贴与纯文本粘贴；
- 若浏览器不支持 ClipboardItem 富文本写入，自动回退到隐藏可编辑节点的 `execCommand("copy")`；
- 排版器界面提示“复制富文本需 localhost 或 HTTPS”，符合浏览器安全上下文要求。

### 4.4 防误操作与状态反馈

- 文稿编辑后未重新排版时，预览置灰并提示“文稿有更新”，阻止复制旧版；
- 右上角显示字数与预计阅读时长，左下角实时展示已识别结构；
- 一键排版/复制成功均有 Toast 反馈，复制按钮变为“已复制 ✓”；
- 所有处理都在当前浏览器完成，内容不会上传到任何服务器。

## 5. 产品亮点

- **开箱即用**：无登录、无 API Key、无后端，本地/在线均可跑；
- **确定性强**：排版是本地规则，不是模型“猜”，同一输入永远同一输出；
- **品牌可控**：样式锁死，避免小编自行改色导致品牌漂移；
- **隐私友好**：内容不出浏览器，适合品牌内部稿件场景；
- **交付完整**：附真实示例、前后对比截图、演示脚本、测试报告和完整代码仓库。

## 6. 当前缺点与边界（如实说明）

- 未在真实微信公众号编辑器完成端到端粘贴验证（本项目没有公众号后台权限），需要提交者在有权限的环境做最后一步人工验收；
- 暂不支持正文配图、封面图、动图、表格、代码块等多媒体块；
- 语法识别基于规则，复杂文档（如从 Word 复制过来的混乱换行）需要先整理；
- 副标题识别是启发式（短行），个别文章可能误判，但不会丢内容，仅影响样式归类；
- 不支持多品牌模板切换（本次只做 DeepSeek 一个品牌）；
- 不支持批量排版、历史记录、云端保存；
- 剪贴板富文本能力依赖浏览器安全上下文，Chrome/Edge 支持较好，Safari 的 HTML 写入支持有限，需真机验证。

## 7. 后续演进方向（非本次范围）

1. 多品牌模板中心：一套引擎、多套 Token 配置；
2. 从 Word/网页粘贴时自动清洗格式；
3. 支持图片与封面素材库；
4. 接入 DeepSeek 模型做“草稿精修/摘要/标题建议”等增值功能；
5. 团队协作：品牌模板版本管理与发布记录。
